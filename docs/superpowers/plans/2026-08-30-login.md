# 로그인 기능 (OAuth2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MotivHub_FE에 소셜 로그인(OAuth2) 흐름 전체(로그인 → 콜백 → 온보딩 닉네임 설정 → 마이페이지 → 로그아웃/탈퇴)를 신규 Vite+React 프로젝트로 구현한다.

**Architecture:** Zustand 스토어(`authStore`)가 accessToken(메모리)/refreshToken(localStorage)/user를 보관하고, axios 인스턴스의 요청/응답 인터셉터가 이 스토어를 직접 읽고 써서 인증 헤더 첨부와 401 시 리프레시-재시도를 처리한다. 화면 간 이동은 React Router, 서버 데이터 조회는 TanStack Query를 사용한다.

**Tech Stack:** Vite, React 18, TypeScript, React Router, TanStack Query, Zustand, axios, Tailwind CSS v4

## Global Constraints

- 백엔드 오리진: `http://localhost:8080` (env var `VITE_API_BASE_URL`)
- 프론트 dev 서버 포트: `3000` 고정 (`vite.config.ts`의 `server.port`) — 백엔드 기본 `FRONTEND_URL`과 일치
- OAuth 시작 URL: `GET {VITE_API_BASE_URL}/oauth2/authorization/{provider}`, `provider`는 `google | github | kakao | naver`
- 콜백 URL: `${FRONTEND_URL}/oauth/callback?code={code}` (성공) 또는 `?error=oauth_failed` (실패)
- API 엔드포인트/메서드/바디/응답은 정확히 아래를 따른다 (스펙 원문):
  - `POST /api/auth/exchange` `{ code }` → `{ accessToken, refreshToken }` (인증 불필요)
  - `POST /api/auth/refresh` `{ refreshToken }` → `{ accessToken, refreshToken }` (인증 불필요)
  - `POST /api/auth/logout` (인증 필요) → 204
  - `GET /api/users/me` (인증 필요) → `{ id, nickname, nicknameConfigured, email, profileImageUrl, provider, createdAt }`
  - `GET /api/users/me/mypage` (인증 필요) → `{ nickname, email, profileImageUrl, createdAt }`
  - `GET /api/users/nickname-check?nickname=xxx` (인증 불필요) → `{ available }`
  - `PATCH /api/users/me/nickname` `{ nickname }` (인증 필요) → UserProfileResponse
  - `DELETE /api/users/me` (인증 필요) → 204
- 인증 필요 요청은 `Authorization: Bearer {accessToken}` 헤더 사용
- 쿠키 사용 안 함 (`allowCredentials: false`) — 토큰은 body/header로만 주고받음
- accessToken은 메모리에만 보관(새로고침 시 소실), refreshToken만 localStorage에 persist
- **자동화 테스트 스위트는 이번 범위 밖** (스펙의 "범위 밖" 섹션 참조) — 각 태스크는 `npm run build`(타입체크+번들 성공 여부) 및 명시된 수동 QA로 검증한다
- **커밋 금지**: 어떤 태스크에서도 실행자가 `git commit`을 실행하지 않는다. 각 태스크 완료 후 변경된 파일을 요약만 하고, 커밋은 사용자가 직접 진행한다
- 현재 `feature/auth` 브랜치에서 작업한다 (이미 생성되어 있음)

```ts
import { create } from 'zustand'
import { persist } from 'zustand/middleware'
import type { UserProfile } from '../api/types'

interface AuthState {
  accessToken: string | null
  refreshToken: string | null
  user: UserProfile | null
  isAuthenticated: boolean
  setTokens: (tokens: { accessToken: string; refreshToken: string }) => void
  setUser: (user: UserProfile) => void
  clear: () => void
}

export const useAuthStore = create<AuthState>()(
  persist(
    (set) => ({
      accessToken: null,
      refreshToken: null,
      user: null,
      isAuthenticated: false,
      setTokens: ({ accessToken, refreshToken }) =>
        set({ accessToken, refreshToken, isAuthenticated: true }),
      setUser: (user) => set({ user }),
      clear: () =>
        set({ accessToken: null, refreshToken: null, user: null, isAuthenticated: false }),
    }),
    {
      name: 'motivhub-auth',
      partialize: (state) => ({ refreshToken: state.refreshToken }),
    }
  )
)
```

### Task 3: axios 클라이언트 (요청/응답 인터셉터, 리프레시 중복 방지)

**Files:**

**Interfaces:**
- Consumes: `useAuthStore` (Task 2), `AuthTokens` (Task 2)
- Produces: `apiClient: AxiosInstance` (인증 필요 API가 사용), `refreshTokens(): Promise<AuthTokens>` (App 부트스트랩과 인터셉터 양쪽에서 재사용)

- [ ] **Step 1: `src/api/client.ts` 작성**

```ts
import axios, { type AxiosError, type InternalAxiosRequestConfig } from 'axios'
import { useAuthStore } from '../stores/authStore'
import type { AuthTokens } from './types'

const API_BASE_URL = import.meta.env.VITE_API_BASE_URL as string

export const apiClient = axios.create({
  baseURL: API_BASE_URL,
})

apiClient.interceptors.request.use((config) => {
  const { accessToken } = useAuthStore.getState()
  if (accessToken) {
    config.headers.set('Authorization', `Bearer ${accessToken}`)
  }
  return config
})

let refreshPromise: Promise<AuthTokens> | null = null

export async function refreshTokens(): Promise<AuthTokens> {
  const { refreshToken } = useAuthStore.getState()
  if (!refreshToken) {
    throw new Error('No refresh token available')
  }
  const response = await axios.post<AuthTokens>(`${API_BASE_URL}/api/auth/refresh`, {
    refreshToken,
  })
  return response.data
}

type RetryableConfig = InternalAxiosRequestConfig & { _retry?: boolean }

apiClient.interceptors.response.use(
  (response) => response,
  async (error: AxiosError) => {
    const originalRequest = error.config as RetryableConfig | undefined

    if (error.response?.status !== 401 || !originalRequest || originalRequest._retry) {
      throw error
    }
    originalRequest._retry = true

    try {
      if (!refreshPromise) {
        refreshPromise = refreshTokens().finally(() => {
          refreshPromise = null
        })
      }
      const tokens = await refreshPromise
      useAuthStore.getState().setTokens(tokens)
      originalRequest.headers.set('Authorization', `Bearer ${tokens.accessToken}`)
      return apiClient(originalRequest)
    } catch (refreshError) {
      useAuthStore.getState().clear()
      window.location.href = '/login'
      throw refreshError
    }
  }
)
```

`refreshTokens()`는 반드시 `apiClient`가 아닌 순수 `axios`로 호출해야 한다 (`apiClient`로 호출하면 refresh 자체가 401을 받았을 때 인터셉터가 다시 refresh를 시도해 무한 루프에 빠진다).

- [ ] **Step 1: `src/api/auth.ts` 작성**

```ts
import axios from 'axios'
import { apiClient } from './client'
import type { AuthTokens, OAuthProvider } from './types'

const API_BASE_URL = import.meta.env.VITE_API_BASE_URL as string

export function exchangeCode(code: string): Promise<AuthTokens> {
  return axios
    .post<AuthTokens>(`${API_BASE_URL}/api/auth/exchange`, { code })
    .then((res) => res.data)
}

export function logout(): Promise<void> {
  return apiClient.post('/api/auth/logout').then(() => undefined)
}

export function oauthAuthorizeUrl(provider: OAuthProvider): string {
  return `${API_BASE_URL}/oauth2/authorization/${provider}`
}
```

`exchangeCode`는 인증이 불필요한 1회용 코드 교환이므로 `apiClient`가 아닌 순수 `axios`를 사용한다 (인터셉터가 불필요한 헤더를 붙이거나 401 재시도 로직을 타는 것을 방지).

```ts
import { apiClient } from './client'
import type { UserProfile, MyPageProfile, NicknameCheckResponse } from './types'

export function fetchMe(): Promise<UserProfile> {
  return apiClient.get<UserProfile>('/api/users/me').then((res) => res.data)
}

export function fetchMyPage(): Promise<MyPageProfile> {
  return apiClient.get<MyPageProfile>('/api/users/me/mypage').then((res) => res.data)
}

export function checkNicknameAvailable(nickname: string): Promise<NicknameCheckResponse> {
  return apiClient
    .get<NicknameCheckResponse>('/api/users/nickname-check', { params: { nickname } })

export function updateNickname(nickname: string): Promise<UserProfile> {
  return apiClient
    .patch<UserProfile>('/api/users/me/nickname', { nickname })
    .then((res) => res.data)
}

export function deleteAccount(): Promise<void> {
  return apiClient.delete('/api/users/me').then(() => undefined)
}
```

```tsx
import { useAuthStore } from '../stores/authStore'

export function ProtectedRoute({ children }: { children: ReactElement }): ReactElement {
  const isAuthenticated = useAuthStore((state) => state.isAuthenticated)
  if (!isAuthenticated) {
```

```tsx
import { useEffect, useRef, useState, type ReactElement } from 'react'
import { useNavigate, useSearchParams } from 'react-router-dom'
import { exchangeCode } from '../../api/auth'
import { fetchMe } from '../../api/user'
import { useAuthStore } from '../../stores/authStore'

export function OAuthCallbackPage(): ReactElement {
  const [searchParams] = useSearchParams()
  const navigate = useNavigate()
  const setTokens = useAuthStore((state) => state.setTokens)
  const setUser = useAuthStore((state) => state.setUser)
  const [error, setError] = useState<string | null>(null)
  const hasRun = useRef(false)

  useEffect(() => {
    if (hasRun.current) return
    hasRun.current = true

    const code = searchParams.get('code')
    const oauthError = searchParams.get('error')

    if (oauthError) {
      setError('소셜 로그인에 실패했습니다. 다시 시도해주세요.')
      setTimeout(() => navigate('/login', { replace: true }), 1500)
      return
    }

    if (!code) {
      setError('잘못된 접근입니다.')
      setTimeout(() => navigate('/login', { replace: true }), 1500)
      return
    }

    exchangeCode(code)
      .then((tokens) => {
        setTokens(tokens)
        return fetchMe()
      })
      .then((user) => {
        setUser(user)
        navigate(user.nicknameConfigured ? '/mypage' : '/onboarding/nickname', {
          replace: true,
        })
      })
      .catch(() => {
        setError('로그인 처리 중 오류가 발생했습니다. 다시 시도해주세요.')
        setTimeout(() => navigate('/login', { replace: true }), 1500)
      })
  }, [searchParams, navigate, setTokens, setUser])

  return (
    <div className="flex h-screen items-center justify-center">
      {error ?? '로그인 처리 중...'}
    </div>
  )
}
```

`hasRun` ref는 React 18 `StrictMode`가 개발 모드에서 effect를 두 번 실행하는 것을 방지하기 위함이다. `code`는 1회용이므로 두 번 호출하면 두 번째 요청은 반드시 실패한다.
